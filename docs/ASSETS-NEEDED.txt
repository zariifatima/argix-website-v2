ARGIX BRAND ASSETS: STATUS (updated for the "official assets" task)

WHY THEY ARE NOT IN THIS PROJECT YET
The build environment could not download anything from argix.net (its network cannot resolve that host), and the page-reading tool
refuses image URLs. The official asset locations WERE read from the live pages, but the files themselves could not be copied.
Nothing was recreated, traced or invented. The site shows text stand-ins until the real files are present.

HOW TO ADD THEM (one command, on a machine with internet access)
    npm run assets:fetch            # downloads every file below into public/assets/, checking each one
    npm run assets:fetch -- --og    # also takes the live og-image.png (otherwise the temporary one in public/assets stays)
    npm run build
The build detects the files automatically: no code change is needed, and anything missing keeps its text fallback.

DIAGNOSIS OF THE DOWNLOAD FAILURE (re-tested during the Nexavoxa audit task)
  `npm run assets:fetch` -> 27 of 27 files failed ("fetch failed"). Cause: DNS does not resolve argix.net (or nexavoxa.com) in the build
  environment (curl error 6, Node ENOTFOUND). Package registries such as npm do resolve, so this is a network allow-list, not a site outage
  and not a script bug. An earlier test through the egress proxy returned HTTP 403 "host_not_allowed".
  Options: (1) add argix.net to the environment's network allow-list in settings, then re-run `npm run assets:fetch`;
           (2) run `npm run assets:fetch` on your own machine and send back / commit the files in public/assets/;
           (3) attach the logo, client logos and badge files to the chat.
  No substitute, traced or stock artwork is used for any of them.
